# StepSure certificate: analysis and template spec

Source: a sample certificate sent by the client on 10 Oct 2026 (kept out of Git: it contains a participant's personal data). It was made in Adobe Illustrator 29.1 on 5 Aug 2026, as a one-page PDF.

## 1. Format

- **Size: A3 portrait, 297.9 × 421.3 mm** (not A4). The new system will output the same size, so existing printing still works. An A4 version can be offered as well.
- Single page, no bleed marks.

## 3. What changes per certificate (data fields)

1. Participant name
2. Course title
3. Start and end dates, printed as "Held on 3rd–7th August, 2026"
4. Venue, e.g. "Nairobi Safari Club" or "Online"
5. Class/cohort code, e.g. "SOM 3/2026" (**meaning to confirm**)
6. Serial number, e.g. "IA 2/2026" (**meaning to confirm**)
7. Certificate ID, which will be generated by the system
8. QR code linking to StepSure's own verification page (generated)
9. Certificate type: "Participation" (confirm whether other types exist)

Fixed parts: logo, seal, ribbon, signatories (unless they change), background, wording.

## 4. Problems found in the current certificate

1. **The QR code and the ID verify the wrong people.**
   - The QR code opens Zikoro (`credentials.zikoro.com/…/c7b8…`), which shows a *different participant* issued in August 2025.
   - The printed ID (in lower case) shows *another different participant* from September 2025. The ID with a capital C shows "certificate does not exist".
   - The certificate was clearly made by editing an older one in Illustrator, without generating a new credential.
   - Anyone checking the sample certificate would conclude it is not genuine. This is the main reason to move to an automated system where the ID and QR code are always generated together for the right person.
2. **Spelling:** "COMMITTED TO EXELENCE" should read "EXCELLENCE". It's inside the seal image, so it needs a corrected logo or badge file.
3. **Print quality:** the background and the seal are embedded at **72 dpi** on an A3 page, so they will print blurry or pixelated. We need the original high-resolution or vector artwork.
4. **Font licensing:**
   - The name font is a **Fontspring *demo*** ("FONTSPRINGDEMO-Juana"). Demo fonts are licensed for testing only, not for issued documents.
   - Gotham, Rockwell, Century Schoolbook and Constantia are commercial or Microsoft fonts. They need a licence to be embedded by a web system.
   - Our plan is to use close free equivalents, or licensed copies if StepSure owns them.
5. **Small typography issues:** inconsistent spacing in "3rd -7th"; "Has successfully completed" should use a lower-case "has" mid-sentence (optional).
6. **Dependency on Zikoro:** past certificates verify on Zikoro's domain, not StepSure's.

## 5. Proposed font substitutes (free for commercial use; to approve)

| Original | Substitute | Notes |

| Juana Italic (demo) | Playfair Display Italic or Cormorant Garamond Italic | Elegant italic serif for the name |

| Rockwell Italic | Roboto Slab or Arvo Italic | Slab serif |

## 6. Assets needed from StepSure

1. **The original Illustrator file (.ai)** of the certificate, or at least:
   - the background artwork (swooshes, cream texture, watermark) at 300 dpi or as vector;
   - the ribbon and seal badge as a transparent PNG at 300 dpi or SVG, with the spelling fixed;
   - the StepSure logo as SVG or a high-resolution PNG.
2. **Signatures** of Martin Oduor and Hannah Mwaura: black ink on plain white paper, scanned at 300 dpi (we'll make them transparent). Confirm they're still the signatories.
3. **Zikoro account access, or an export of past certificates** (name, course, dates, ID). Zikoro can probably export these, which would give us the "past certificates spreadsheet" without manual work.

## 7. Questions for the client

1. What do **"SOM 3/2026"** and **"IA 2/2026"** mean, and how are they numbered? (E.g. class code = programme + intake number/year; serial = running number per year?)
2. Are there other certificate types besides **Participation** (e.g. Completion, Attendance, Merit)? Same design?
3. Should the new **Certificate ID** follow a format they like (e.g. `SS-2026-000123`), or keep a random 12-character code as on Zikoro?
4. Do they **print** certificates (A3 or A4?) or send them digitally only?
5. Should certificates be **emailed** to participants automatically, and from which address?
6. Is the **Zikoro** subscription still active? Plan: keep it so old QR codes keep working, import past records into the new system, and issue all new certificates on StepSure's own domain.
7. Who in their team will issue certificates? (We'll create their logins.)
8. Should the verification page show the venue and dates, or only the name, course and date?

## 8. Plan

- **Verification address:** `certificates.stepsureresearchinstitute.org/verify/{code}`. A one-line DNS record is needed in NameSilo.
- **Template:** rebuild the design as an HTML/PDF template (done: see stepsure-portal) at the original A3 size, using the high-resolution assets and fonts above, so the output matches the current look.
- **Admin:** issue one certificate, or upload an Excel/CSV list for a whole class. Download the PDFs individually or as a ZIP. Email to participants. Revoke a certificate if needed. Import past certificates.
- **Engine:** reuse the tested Geovani certificate engine.
